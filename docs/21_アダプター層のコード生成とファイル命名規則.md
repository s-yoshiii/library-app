## アダプター層のファイル構成

クリーンアーキテクチャにおけるアダプター層は、アプリケーション層とインフラ層をつなぐ役割を持つ。

```
src/adapter/
├── controllers/
│   ├── bookController.ts       # Book エンティティのコントローラー
│   └── userController.ts       # User エンティティのコントローラー（スキャフォールド）
├── repositories/
│   ├── prismaBookRepository.ts # Book の Prisma 実装
│   └── prismaUserRepository.ts # User の Prisma 実装（スキャフォールド）
└── utils/
    └── uuidGenerator.ts
```

### ファイル命名規則

| 種類 | 命名パターン | 例 |
|---|---|---|
| コントローラー | `${entityName}Controller.ts`（camelCase） | `bookController.ts` |
| Prisma リポジトリ | `prisma${EntityName}Repository.ts`（小文字 prisma + PascalCase） | `prismaBookRepository.ts` |

**ポイント**: `Prisma` ではなく `prisma`（小文字）が正しい。ファイル名はクラス名とは異なる（クラス名は `PrismaBookRepository`）。

## 各ファイルの役割

### コントローラー（`bookController.ts`）

HTTP リクエストを受け取り、ユースケースを呼び出してレスポンスを返す。

```typescript
export class BookController {
  constructor(
    private readonly addBookUseCase: AddBookUseCaseInterface,
    private readonly findBookByIdUseCase: FindBookByIdUseCaseInterface,
  ) {}

  async add(req: Request, res: Response): Promise<void> {
    const requestDto: AddBookRequestDto = { title: req.body.title as string };
    const book = await this.addBookUseCase.execute(requestDto);
    res.status(201).json(book);
  }
}
```

- コンストラクターにユースケースを注入する（依存性注入）
- `import type` を使う（`verbatimModuleSyntax` の制約）
- エンティティではなく DTO でやり取りする

### Prisma リポジトリ（`prismaBookRepository.ts`）

ドメイン層のリポジトリインターフェースを実装し、Prisma を使って DB 操作を行う。

```typescript
export class PrismaBookRepository implements BookRepositoryInterface {
  constructor(private readonly prisma: PrismaClient) {}

  async findById(id: string): Promise<Book | null> {
    const foundBook = await this.prisma.book.findUnique({ where: { id } });
    if (!foundBook) return null;
    return new Book(foundBook.id, foundBook.title, ...);
  }
}
```

- `implements BookRepositoryInterface` でインターフェースとの契約を保証する
- Prisma の型は `import type` で取り込む（値として使わないため）
- DB のレコードをドメインエンティティ（`new Book(...)`）に変換して返す

## スキャフォールドと「Not implemented」

まだ Prisma スキーマに `User` モデルが存在しないため、`prismaUserRepository.ts` は一時的に `throw new Error('Not implemented')` を返すプレースホルダーになっている。

```typescript
async create(_user: User): Promise<User> {
  throw new Error('Not implemented');
}
```

- 未使用のパラメーターは `_` プレフィックスをつける（TypeScript の警告を抑制）
- `throw` は戻り値を持たないので、どの戻り値型でも型エラーにならない
- Prisma スキーマに `User` モデルを追加したタイミングで実装を埋める

## インポートのルール（復習）

| 状況 | 書き方 |
|---|---|
| クラスや値として使う | `import { PrismaClient } from '...'` |
| 型としてのみ使う | `import type { PrismaClient } from '...'` |
| Express の Request/Response | `import type { Request, Response } from 'express'` |

`verbatimModuleSyntax` が有効なので、型のみのインポートは必ず `import type` にしないとコンパイルエラーになる。
